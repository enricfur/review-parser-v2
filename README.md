# Review Parser V2 — многопоточный парсер отзывов

Учебное приложение на **Java 21, Spring Boot и Maven** для сбора и хранения отзывов с Apple App Store и сайта «Доступное право».

Источники регистрируются через REST API, отзывы собираются в фоновых потоках и периодически обновляются по расписанию. Сохранённые результаты доступны через HTTP в формате JSON. Графический интерфейс не требуется.

## Предыстория и выбор источников

Первоначально в отдельном проекте `review-parser` мною были реализованы сборщики отзывов для трёх площадок: IRecommend, Apple App Store и «Доступное право». Из-за ограничений доступа к IRecommend (HTTP 521, CAPTCHA) для `review-parser-v2` были выбраны две площадки, на которых удалось подтвердить успешный сбор реальных отзывов: Apple App Store и «Доступное право». Первоначально для сбора отзывов использовался Apple App Store. Однако в ходе разработки и тестирования было выявлено, что RSS-интерфейс Apple App Store может работать нестабильно: в отдельных случаях сервер возвращает ответ, не содержащий ожидаемого массива отзывов feed.entry. В результате отдельные попытки сбора могут завершаться ошибкой, несмотря на корректную работу приложения.

Для обеспечения возможности стабильной демонстрации функциональности проекта и проверки требований задания была дополнительно реализована поддержка второго независимого источника — сайта «Доступное право».

Таким образом, проект позволяет продемонстрировать регистрацию источников, многопоточную обработку, автоматический сбор по расписанию и сохранение отзывов в базе данных H2 на двух разных площадках.

При возникновении ошибки получения данных из Apple App Store приложение фиксирует состояние FAILED, не удаляя ранее сохранённые отзывы. Последующие попытки сбора могут завершиться успешно.

`review-parser-v2` создан как отдельная реализация учебного задания с последовательным выполнением четырёх этапов.

## Быстрый старт

Для запуска необходимы **JDK 21**, подключение к интернету и свободный порт **8080**.

Команды выполняются в **Windows PowerShell** из корневой папки `review-parser-v2`, где находится `pom.xml`. Maven отдельно устанавливать не требуется.

**1. Запуск приложения**

```powershell
.\mvnw.cmd spring-boot:run
```

По умолчанию используется файловая база **H2**. Дождитесь сообщения `Started ReviewParserV2Application` и оставьте приложение работающим.

**2. Регистрация источника**

Во втором окне PowerShell выполните:

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/sources" -Method Post -ContentType "application/json" -Body '{"url":"https://dostupnoepravo.ru/review/companies/310-yuridicheskaya-kollegiya"}'
```

**3. Проверка состояния сбора**

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/sources"
```

**4. Получение отзывов**

```powershell
(Invoke-RestMethod -Uri "http://localhost:8080/answer").Count
```

Сбор выполняется асинхронно. Если сразу после регистрации отзывов ещё нет, необходимо проверить статус источника и повторить запрос после завершения задачи.

## Реализованная функциональность

Мною последовательно реализованы четыре этапа задания:

- **Этап 1 — Spring MVC и REST API.** Регистрация источников, получение отзывов, обработка ошибок, модульные и интеграционные тесты.
- **Этап 2 — `Thread` и `Runnable`.** Асинхронный сбор, параллельная обработка разных источников, состояния задач `QUEUED`, `RUNNING`, `COMPLETED`, `FAILED` и защита от одновременного повторного сбора одного источника.
- **Этап 3 — `ExecutorService`.** Пул из четырёх рабочих потоков (`ThreadPoolExecutor`), блокирующая очередь на восемь задач (`ArrayBlockingQueue`), планировщик (`ScheduledExecutorService`), синхронизация через `synchronized`, JSON-хранение и демон-поток для журналирования состояния пула.
- **Этап 4 — H2 и `parallelStream()`.** Хранение источников и отзывов через Spring JDBC/H2, транзакционное сохранение отзывов, фильтрация по минимальной оценке и сортировка по оценке или дате публикации.

На втором этапе фоновый сбор был реализован с использованием `Thread` и `Runnable`. На третьем этапе управление задачами переведено на ограниченный пул `ExecutorService` с блокирующей очередью. В итоговой версии задачи `Runnable` выполняются рабочими потоками пула.

При неудачном повторном сборе ранее успешно сохранённые отзывы остаются доступными. По умолчанию планировщик автоматически обновляет зарегистрированные источники каждые 60 секунд.

## Подробная проверка работы

После запуска приложения HTTP API доступен по адресу `http://localhost:8080`.

### Регистрация второго источника

Пример для Apple App Store (Telegram):

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/sources" -Method Post -ContentType "application/json" -Body '{"url":"https://apps.apple.com/ru/app/telegram-messenger/id686449807"}'
```

Метод `POST /sources` возвращает **HTTP 202 Accepted**: задача принята, но сетевой сбор может ещё выполняться.

Повторная регистрация того же URL не создаёт новый источник. Если сбор уже выполняется, вторая одновременная задача для этого источника не запускается.

### Просмотр источников и статусов

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/sources" | Format-List
```

Ответ содержит `id`, `url` и текущий `status`.

Возможные состояния: `QUEUED`, `RUNNING`, `COMPLETED`, `FAILED`.

Статусы текущих задач хранятся в памяти. После перезапуска у восстановленных источников поле `status` может быть пустым до очередного сбора.

### Получение отзывов отдельного источника

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/answer?sourceId=1"
```

Здесь `sourceId=1` приведён для примера. Фактические идентификаторы можно получить через `GET /sources`.

Каждый отзыв содержит поля `externalId`, `sourceUrl`, `author`, `title`, `content`, `rating` и `publishedAt`.

### Фильтрация и сортировка

Количество отзывов с оценкой не ниже 4:

```powershell
(Invoke-RestMethod -Uri "http://localhost:8080/answer?minRating=4").Count
```

Первые десять оценок после сортировки по убыванию:

```powershell
(Invoke-RestMethod -Uri "http://localhost:8080/answer?sortBy=rating&direction=desc").rating | Select-Object -First 10
```

Сортировка по дате, начиная с новых отзывов:

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/answer?sortBy=publishedAt&direction=desc"
```

Поддерживаются необязательные параметры:

- `sourceId` — идентификатор источника.
- `minRating` — минимальная оценка.
- `sortBy` — `rating` или `publishedAt`.
- `direction` — `asc` или `desc` (по умолчанию `asc`).

Параметры можно комбинировать. Без параметров `GET /answer` возвращает все сохранённые отзывы.

Фильтрация и сортировка выполняются через `parallelStream()` над полученными из хранилища отзывами.

### Автоматическое обновление

В обычном режиме `ScheduledExecutorService` периодически запускает повторный сбор зарегистрированных источников без дополнительных POST-запросов.

Интервал задаётся свойством `review.collection.schedule-interval-seconds`. Значение по умолчанию — 60 секунд.

### Проверка сохранения после перезапуска

Для проверки восстановления данных без повторного обращения к внешним сайтам остановите приложение сочетанием **Ctrl+C** и запустите с временно отключённым планировщиком:

```powershell
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.arguments=--review.collection.schedule-interval-seconds=0"
```

После запуска повторите запросы:

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/sources" | Format-List
```

```powershell
(Invoke-RestMethod -Uri "http://localhost:8080/answer").Count
```

Ранее сохранённые в H2 источники и отзывы останутся доступными без нового сетевого сбора.

Для возвращения обычного режима остановите приложение и запустите его без параметров.

## Хранение и настройки

В `src/main/resources/application.properties` установлен режим хранения:

```properties
review.storage.mode=h2
```

По умолчанию данные сохраняются в файловую базу H2 `data/review-parser-v2-db`. Структура таблиц определяется файлом `src/main/resources/schema.sql`.

Также поддерживается альтернативное хранение в JSON. Для его включения используется команда:

```powershell
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.arguments=--review.storage.mode=json"
```

В этом режиме источники сохраняются в `data/sources.json`, а отзывы — в `data/reviews.json`.

Данные H2 и JSON хранятся отдельно и автоматически между режимами не переносятся.

В чистом клоне репозитория ранее собранных отзывов нет. После первого запуска необходимо зарегистрировать источники через REST API.

## Ограничения

Парсер предназначен для поддерживаемых страниц приложений Apple App Store, а также страниц компаний и юристов сайта «Доступное право», а не для произвольных сайтов.

**Для каждого источника обрабатывается не более трёх страниц отзывов.** Если отзывов больше, результат может быть неполным.

Работа приложения зависит от доступности внешних сайтов и сохранения формата предоставляемых ими данных. При ошибках повторного сбора ранее сохранённые отзывы остаются доступными.
